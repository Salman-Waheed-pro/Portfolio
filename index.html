Why do AI answers drift from what people need?

An answer can be correct and still too long, too vague, or useless for the problem in front of you. My thesis separates correctness, concreteness and value, traces the gap back to how the model generates text, and tests a fix against whichever cause dominates.

2026 BeaconMed An ERP for pharmaceutical distributors in Pakistan, deployed and in testing with a pilot client. DeployedArchitectureInfrastructurePrivate code

A pharmaceutical distributor was running invoices, batch stock and customer credit on spreadsheets and an old desktop app. Pakistani sales-tax law (Section 23) and DRAP rules decide what every invoice has to carry, and expiry dates decide which batch ships first. Getting either wrong is a legal problem, not a UX one.

I'm the product owner, architect and the person who runs the server. An AI coding agent wrote most of the code. I wrote the requirements, designed the system, reviewed every one of roughly 85 merged pull requests before it went in, and hardened and operate the infrastructure.

  • Multi-tenant from day one, with Postgres row-level security so one distributor can never read another's data, even through a bug in the API.
  • First-expiry-first-out batch allocation in the warehouse.
  • An offline-first mobile app for salesmen in the field, since connectivity there can't be assumed.
  • Docker Compose behind Caddy, Cloudflare in front, Tailscale for admin access, encrypted backups to off-site storage. About €10.50 a month to run.

2026 Oppipolku Market intelligence for continuing education: should we launch this programme, and at what price? ProductData pipelineLLM assistantPrivate code

Universities price continuing-education programmes from cost and launch them on instinct. Our design partner, an executive-education unit in Istanbul, had cancelled a leadership programme after launch because too few people enrolled. The data that could have warned them was public, just scattered across hundreds of competitor pages.

Oppipolku turns those pages into an answer. Scrapers collect programme listings, each record keeps its source URL and capture date, names are normalised and matched across institutions (ambiguous matches go to a human, never a guess), and the pipeline produces demand and pricing signals and a one-page launch assessment. An assistant sits on top, but every number it quotes comes from server-side tools, so it can't make one up.

The Finnish version is an LLM assistant for open-education questions, now being tested with staff at TAMK.

Every number traces back to a URL. That rule shaped the whole architecture.

Role
Product owner, delivery lead, UX and sales, and the client relationship. Built with two teammates on engineering and security review; most of the work on the project is mine.

2026 Pakistan real estate AI Price prediction and budget-matched recommendations over 45 MB of property listings. Machine learningStreamlitPublic code

I picked a market I know well enough to tell when the model is wrong. The pipeline cleans the listings (including converting Pakistani area units), trains a Random Forest and an XGBoost model, and a Streamlit app predicts a fair price and ranks listings that look underpriced for a given budget.

Random Forest won on all three metrics without tuning: R² 0.885 against 0.866, and a mean error of PKR 2.46M against 2.84M.

The part I find most useful is a flaw. A neighbourhood the model never saw in training isn't rejected; it silently falls back to whichever location sorts first alphabetically, and gets priced as somewhere else. The model looks confident for exactly the users it knows least about. I kept it in and documented it, because that failure is the reason my thesis is about evaluation.

Stack
Python, pandas, scikit-learn, XGBoost, Streamlit

2026 SDLC governance for coding agents A lifecycle an AI coding agent has to follow, with gates it can't talk its way past. Developer toolingClaude Code pluginPublic code

Coding agents are fast and agreeable, which is a bad combination for the boring checks that keep production safe. I wrote a file-based operating system for software projects: phases from inception to operations, each with deliverables and hard gates, and a verification rule for every deliverable (a file that must exist, a command that must pass, a pattern that must not appear). The agent has to find evidence in the repository before it ticks anything off, and the files become the audit trail.

The second version packages it as a Claude Code plugin with two commands: /govern runs the current phase, and /inspect is a read-only auditor that checks the project for completeness and sweeps it against the OWASP Top 10. I built it while running BeaconMed, which is where the gates came from.

2026 Cloudberry Scout Ranking Finnish mires by how likely they are to hold a good cloudberry harvest. GeospatialRemote sensingPublic code

I pick cloudberries, and every map app shows a hundred identical swamp symbols. This pipeline fuses Finnish open data into a ranked short list with a column for each reason a bog scored the way it did: distance from drainage ditches, peatland site type, openness and moisture from Sentinel-2, flatness and hummocks from LiDAR, and frost risk scaled by this year's weather.

It's upfront about its ceiling. Only female cloudberry plants fruit, and ripeness is a timing problem, so no satellite can promise a full bucket. The score is better odds per bog visited, and it says so in the first paragraph of the README.

03 / How I work

Ambition, with a test set

i

Build it before I claim it

If a skill isn't on a real project yet, I build a small one first. The CV comes after the commit.

ii

Measure the thing, not the demo

A demo shows the best case. A hundred checked questions and an error taxonomy show where it breaks, and that's what people need to trust it.

iii

Say the hard constraint early

Data that can't leave a factory, a law about invoices, a Finnish level of A1. Easier to design around on day one than to discover in week six.

iv

Treat AI output like a pull request

I work with coding agents every day. Their code gets the same reading, testing and gates a teammate's would, and the decisions stay with me.
